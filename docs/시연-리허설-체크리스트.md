# 시연 리허설 체크리스트

시연은 **3단 백업**으로 준비합니다. 강의 주제인 "가드레일은 겹겹이"를 시연 준비에도 그대로 적용한 구조입니다.

| 순서 | 실행 | 필요 조건 |
|---|---|---|
| 1 (기본) | `python guardrail_demo.py` (로컬 gemma3:27b) | WSL Ollama, 모델 미리 다운로드 |
| 2 (백업) | `python guardrail_demo.py --backend bedrock` | 인터넷, `.env`의 IAM 키 |
| 3 (최종) | `python guardrail_demo.py --backend mock` | 없음 |

## 전날

- [ ] `git pull` 로 최신 코드 받기
- [ ] `ollama list` 에 `gemma3:27b`, `llama3.2` 있는지 확인 (현장 와이파이로 대용량 다운로드 금지)
- [ ] `python bedrock_gemma_demo.py --list ap-northeast-2 ap-northeast-1 us-west-2`로 후보 확인 → 선택한 `AWS_REGION`, `BEDROCK_MODEL_ID`를 `.env`에 설정 → `python check_env.py`로 실제 호출 확인
- [ ] 인터넷을 끊고 `python guardrail_demo.py` 실행 → 로컬만으로 동작 확인
- [ ] 노트북 전원 어댑터, HDMI/USB-C 영상 어댑터 챙기기

## 현장 (시작 10분 전)

- [ ] 외부 화면 연결, VS Code 글꼴 크기 확인 (설정 18)
- [ ] 작업 **예열: Ollama gemma3:27b 로딩** 실행 (첫 호출은 모델 로딩으로 수십 초 걸릴 수 있음)
- [ ] 작업 **모니터: GPU** 를 터미널 옆 창에 띄워 두기
- [ ] **시연 전 환경 점검** 실행

## 시연 중 말할 한 문장

> "지금 화면의 답은 인터넷이 아니라 이 노트북 GPU 안에서 Gemma 3가 만든 것입니다. 데이터가 밖으로 나가지 않는 것, 이것이 Private LLM입니다. 그래도 모델은 실수하니 앞뒤에 가드를 둡니다."

## 문제가 생기면

| 증상 | 조치 |
|---|---|
| 로컬 LLM 연결 안 됨 | WSL에서 `ollama serve` 확인 → 안 되면 ④ Bedrock |
| 응답이 너무 느림 | `--model llama3.2` 로 전환 (속도·품질 비교 소재로 활용) |
| Bedrock AccessDenied | IAM 정책(docs/iam-policy-bedrock-gemma.json)의 호출 ARN이 선택한 리전·모델(기본 ap-northeast-1)과 일치하는지 확인 → 안 되면 모의 LLM |
| 모두 실패 | 슬라이드 "다섯 가지 요청" 표로 설명 |
